# NERO / Piper 推理平台

仅面向 NERO 和标准六关节 Piper。本次按用户要求完成第 3、4 步，只接入 π0.5，OpenWAM 暂不接入。
平台代码、网页资源和测试集中在 `examples/inference_platform/`，可直接从 LeRobot 项目启动。

| 步骤 | 范围 | 状态 |
| --- | --- | --- |
| 1 | 深色工作台、机械臂类型、单/双臂、关节空间/EEF、模型与 checkpoint、任务和保存配置 | 已完成 |
| 2 | 机械臂与相机连接、微动辨认、角色确认、三路实时预览 | 已实现，等待用户验证 |
| 3 | π0.5 加载、动作规格校验、单段执行、停止、回初始位置 | 已实现；已完成离线模型与模拟设备验证，待真机验收 |
| 4 | 持续闭环执行、LeRobot 视频/数据保存与收尾 | 已实现；已完成模拟执行与实际文件写入验证，待真机验收 |

停止控制随第一项真实运动一同接入，不会先开放单段执行再补停止。
关节空间与 EEF 是不同的模型输入/输出约定，切换 UI 不会转换 checkpoint。
NERO 和 Piper 的关节数、运动学及设备适配分别处理，不扩展其他机械臂。

## 启动

```bash
conda activate lerobot
cd /home/jushen/Documents/Robot/lerobot
python examples/inference_platform/run.py
```

打开 <http://127.0.0.1:7862/>；在启动终端按 `Ctrl+C` 关闭。
当前 `lerobot` 环境已具备所需依赖。打开网页不会自动连接设备；在页面点击连接后才读取 CAN 或相机。
设备适配使用本 LeRobot 项目的 `examples/nero_to_nero/nero_platform` 相机模块，以及现有 `pyAgxArm` SDK，不依赖相邻的 Nero 项目。
其他环境可先安装页面依赖；设备连接还需要本项目的 LeRobot 环境、OpenCV、NumPy、pyAgxArm，以及对应 RGBD 相机的 SDK：

```bash
python -m pip install -r examples/inference_platform/requirements.txt
```

可用 `--port 7863` 修改端口。Nero 项目原来的 `nero_platform_web.py` 仅转发到这里，方便兼容旧命令。

Checkpoint 来源仅有两种：

- **扫描 outputs 文件夹**：只递归扫描本 LeRobot 项目的 `outputs/`，按基座模型筛选结果；不扫描 Downloads，也不跟随指向外部目录的链接。默认显示扫描结果中的首项，可在扫描结果里选择具体训练步数。
- **手动选择文件夹**：立即打开本机系统文件夹窗口，选择包含 `config.json` 或 `config.yaml` 的 checkpoint 目录；也可选择包含 `pretrained_model` 的训练步数目录。取消后保留原选择。

窗口使用 Linux 桌面的 `zenity`（当前机器已安装），须在本机桌面启动平台。只返回路径和读取配置，不上传权重。原 `--checkpoint-dir` 参数已移除，外部模型统一通过手动选择。
配置保存到当前浏览器的 localStorage；刷新后重新检查已手动选择的目录，不自动弹出窗口。旧版自动列表中保留的 Downloads 项不再混入 outputs 结果。
不会仅凭动作维数、文件夹名或训练数据集名推断动作空间和机械臂型号。
加载时严格校验动作名称、顺序、维数、相机字段和保存的预处理器；无需连接或确认设备，不发送硬件命令。执行前才校验用途确认、相机映射与实际设备反馈。支持的单位与坐标约定见下文；checkpoint 未声明的机器人型号和物理标定不能由名称自动认证。

## 第二步使用与验收

1. 先选择 NERO / Piper、单臂 / 双臂、关节空间 / EEF，然后点击“连接机械臂”或“连接相机”，打开同一个设备面板。
2. 点击“重新检测设备”。CAN 通道显示 USB 标识和启动状态；平台不会自动执行 `sudo` 或修改 CAN 配置。若未启动，请先按已有设备流程启动 CAN，再检测。
3. 对需要的 CAN 点击“连接并读取反馈”。应显示更新的关节角和夹爪开度。点击卡片里的“微动测试”，确认通道和周围空间后开始，用实物动作辨认设备，再分配用途。单臂和双臂模式都提供“左主臂 / 右主臂 / 左从臂 / 右从臂”四种身份。单臂选择一个左/右从臂，双臂选择左右从臂；主臂可选，不计入模型执行臂数。不能把同一用途分给两台设备，也不能仅凭 USB 标识推断实物位置。分配用途只记录实物身份，不触发硬件模式切换或主从联动。
4. 对相机点击“打开预览”，根据实际画面选择头部、左腕、右腕。可只用一台相机，最多分配三路；是否满足所选模型的图像要求留到第三步校验。USB 相机直接复用采集平台的 640×480 / 30 FPS 设备预览、RGB 转换和 JPEG 编码，并读取 `examples/nero_to_nero/collect_config.platform.json` 中按设备保存的对焦设置（不存在时沿用采集平台的旧配置迁移）。共用初始化在设备支持时开启自动白平衡并读回；失败会显示提示，不写入固定色温。采集预览、正式录制和推理都调用这个初始化。RGBD 复用原 SDK 适配，当前页面显示 RGB。
5. 核对实物用途后，可直接在主页面点击“确认本次设备用途”，或在设备面板勾选确认后点击“确认设备用途”。只校验本次分配的设备，未分配设备正常忽略；单主从训练对应单臂推理，其余两条臂不必分配。只有本次分配的设备均有有效新反馈、含所需从臂与至少一台相机时才会通过。
6. 验证刷新页面后连接仍在；点击“断开全部设备”后画面消失、连接释放；再连接时需要重新确认。程序退出后不自动恢复硬件连接。

连接操作只建立通信、读取普通/示教关节反馈与夹爪开度、预览相机。只有明确点击“开始微动”才切换从臂模式、使能和发送动作。示教反馈可显示，但不能据此确认从臂可用于推理或启动微动。
关节空间 / EEF 仍是模型动作约定；本步的关节反馈不冒充模型 EEF 输入，也不转换 checkpoint。
反馈中断、设备拔插、用途变化或重新连接会取消用途确认。失去新帧时清除画面，不持续显示旧图。
连接由服务进程共享，多标签页看到同一连接状态；浏览器刷新不会重复打开设备。
连接后仍可直接修改配置：单臂 / 双臂、关节空间 / EEF 保留所有连接和用途分配，只取消用途确认；切换 NERO / Piper 会释放原机械臂连接，保留相机预览和用途分配，随后按新类型重新连接机械臂。双臂切单臂不会擅自选边，若已分配两个从臂，请取消其中一个用途后确认。微动期间需先停止并等待停稳；重新枚举插拔的设备仍需断开后检测。
关闭浏览器不等于释放硬件；请使用“断开全部设备”或在终端按 `Ctrl+C`。

### 微动测试

- NERO 测试 J7，标准六关节 Piper 测试 J6，固定向限位中间方向转动 5° 后返回测试前位置，使用 `move_j` 规划运动、5% 速度。其余关节目标保持原位，夹爪不下发指令；这不是“回初始位置”。
- 微动是独立的关节识别动作，关节空间 / EEF 两种模型配置下均可使用，不加载模型。一次只测试一台臂；微动期间锁定用途修改和确认。
- 点击前会显示具体型号、CAN 通道、用途和动作。测试会使能并切换从臂受控模式，结束后保持使能及 5% 速度，不自动恢复示教联动、不自动失能。
- 动作前要求普通关节、每个关节的驱动和控制器均有新反馈，控制器没有故障，SDK 与控制器限位均有效。普通姿态及 Piper 的起点与目标须位于二者交集内。
- NERO 已知收拢姿态采用独立的辨认范围：本机四臂曾反馈 J2 约 −101.4°、J4 约 125.8°、J7 约 94.9°–97.2°，上一版把这些起点直接按规划限位拒绝，导致点击后不动作。现仅在接近收拢姿态、且偏差满足专用窗口时允许 J7 向内 5° 后返回；其余关节目标逐值保持原位。窗口中心为 `[0, -100, 0, 123, 0, 0, 95]°`，识别容差为 `[5, 2, 5, 4, 5, 5, 3]°`；超出限位只允许 J2 向下最多 2°、J4 向上最多 4°、J7 向上最多 8°。这些是本机反馈识别窗口，不是机械行程限位，也不用于模型执行或回位。
- 收拢姿态的反馈还受相对起点范围约束：非腕关节偏离超过 0.5°、J7 超过向内 5.5° 或向外 0.3° 即中止。当前安装的 SDK 默认未开启目标裁剪；若已开启，收拢姿态微动会拒绝执行，平台不会关闭这个设置或修改控制器限位。异常退出仍按相同的停止/急停流程处理。
- 提交、执行、完成和失败都显示在对应 CAN 卡片的按钮下方，失败原因用红色标出。若页面和运行中的服务版本不一致，会提示先重启服务。
- 设备面板的“停止微动”、底部停止按钮及 Esc 都能取消。正常取消保持当前反馈位置，不继续返回；无法确认停稳时尝试电子急停并禁止再次微动，需处理硬件问题后重启平台。网页停止不能替代实体急停。
- 发起微动的页面每 300 ms 续约；关闭面板、切到后台、刷新或关闭页面会取消，心跳超过 1.5 s 未到达也会取消。其他标签页可查看或停止，但不会替原页面续约。断开设备与退出服务先取消微动、处理停止，再关闭通信。

旧 OpenWAM 推理工作台与本平台共享设备占用锁；其他采集程序不使用这个锁，连接前应先结束其设备会话。
若驱动报告释放失败，页面会保留异常并阻止重复打开；退出平台、检查设备后重试。
Piper 目前接入标准六关节 Piper 的基础反馈协议，仍需用户真机验收；Piper H/L/X 暂不扩展。

## 第一步配置回归

1. NERO / Piper、单臂 / 双臂、关节空间 / EEF 切换是否直观，页面空间是否合适。
2. 来源仅显示“扫描 outputs 文件夹 / 手动选择文件夹”两项，扫描提示明确只查找本项目 outputs。选择手动来源应弹出系统窗口，取消保留原选择。
3. 选择 π0.5 → `pi05_right_arm_pick / 015000`：选择 NERO、单臂、关节空间后应显示 8 维动作；切到 Piper 应提示关节数不匹配。
4. OpenWAM 选项标为“暂不接入”；填写任务、切换保存数据开关、点击“保存配置”，刷新后恢复。

## 第三、四步使用与验收

1. 按 checkpoint 选择机械臂类型、单/双臂和关节/EEF。连接、分配本次使用的设备，闲置设备保持未分配。
2. 选择 checkpoint，点击“加载 π0.5”，不要求事先确认或连接设备。独立进程在本机加载权重，预览保持可用。读取 checkpoint 自带的 tokenizer、归一化和后处理；缺文件、权重不匹配直接报错，不下载替代模型、不以随机权重继续。执行前在主页面核对设备列表并点击“确认本次设备用途”。
3. 填写任务与「单集测试时长」，点击“单集测试”：读取最新 RGB 和机械臂原始反馈，闭环预测并逐段执行，到设定时长后自动停止并保持。
4. “持续执行”每段结束后重新读取观测并预测，直到手动停止。首版按段同步执行，预测期间保持上一目标，不使用 RTC 或后台提前下发。点击“停止执行”或 Esc 停止；关闭/切换页面或 1.5 秒心跳失联也会停止。停止不再释放模型，停止后单集测试与持续执行都可再次运行。
5. “回到初始位置”无需加载模型，仅移动已确认的从臂。NERO 直接引用采集平台的 `[0,-100,0,120,0,0,90]°`，Piper 为六关节零位；双臂逐臂回位，速度 10%，夹爪不动作。回位目标仍需通过本机限位校验。
6. 勾选“保存本次运行”再执行。每次单集测试或持续运行生成独立目录：`保存根目录/owner/name/日期时间-随机号/`，默认根目录为 `outputs/inference`。不续写或覆盖原采集数据，不上传。

### 支持的 π0.5 数据约定

- 关节：每臂 NERO 7 关节 / Piper 6 关节，弧度；夹爪物理开度 0–0.1 m。名称为 `joint1.pos … gripper.pos`，双臂按 `left.*` 再 `right.*`。
- EEF：每臂 `xyz`（米，SDK 基座坐标），旋转矩阵前两列按列展开 6 维，夹爪 `20*开度(m)-1`，共 10 维。名称须明确为 `eef_x/y/z`、`rot6d_col0/1_x/y/z`、`gripper`。NERO FK/IK 复用现有 `nero_dual_eef`，Piper 用 SDK 的 Piper MDH；不猜测其他坐标系或单位。
- 相机：`head/left/right` 或 `base_0_rgb/left_wrist_0_rgb/right_wrist_0_rgb`，按用途一一映射，缺相机拒绝执行。模型预处理接收原始 RGB，预览和录制共用已有相机连接。
- 严格加载本地完整权重与保存的前后处理流水线，支持其相对动作还原；暂不接入 PEFT 与 RTC checkpoint。
- 模型动作段整体检查后才下发：限位取 SDK/控制器交集，相邻关节变化不超过 0.20 rad；EEF IK 残差上限 5 mm / 3°。按 30 Hz 插值，关节速度上限 0.25 rad/s、夹爪 0.02 m/s，大于该速度的段放慢。
- 起点偏移、预测/规划超过 10 秒、控制循环延迟、反馈过期、设备拔插均中止。停止先保持新反馈位置并确认停稳；失败则尝试电子急停并锁定后续运动。网页停止不能替代实体急停，也没有环境碰撞检测。

### 保存内容

使用采集平台相同的 `LeRobotDataset.create/add_frame/save_episode/finalize` 写入：`videos/`、`data/*.parquet`、`meta/`。30 Hz 采样，`observation.elapsed` 保留实际经过时间。`action` 记录下发目标（EEF 为下发关节的 FK），`action.commanded=0` 表示尚未下发或阶段性保持；模型原始预测与推理耗时保存在 `inference.json`。图像为已分配的模型 RGB 输入，不保存深度流。停止或异常时保存已采集的部分，并标注状态；写入故障会停止执行并保留文件。
