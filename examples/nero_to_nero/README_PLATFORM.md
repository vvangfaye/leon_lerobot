# Nero 数据采集工作台

入口是 `record_platform.py`，配置独立保存在 `collect_config.platform.json`。
支持单对主从臂（状态/动作各 8 维）或左右双对（各 16 维）。每对为 7 个关节弧度 + 夹爪宽度米。
支持按左、右、头部角色选择录制相机；已验证的原版 `record_gui.py` 与 `record.py` 保留供独立使用。
各角色可分配普通 RGB、Femto Mega 或 Azure Kinect RGBD；设备插拔不会自动改变已保存的角色和数据字段。
首次无平台配置时可继承原版配置；已有平台配置损坏时不会静默改用默认值。

旧的逐轮验收文档已合并到本文件，避免按过期的“结束采集并失能”流程操作。

横向五列依次为设备检查与相机分配、数据集配置、开始采集、采集区、结束采集。五列按最高一列自动等高，内容增减时保持底部对齐。采集区使用较小的相机卡片，不再铺满大画面。小窗口自动换行；左侧设备和相机列表可以滚动。

- 设备检查：四个 CAN 通道的角色、连接、微动、通信、模式、关节/夹爪使能、故障，以及相机左右分配、取景核对和保存配置。设备操作提示始终显示，只折叠详细关节状态和角度。
- 数据集配置：数据集名、任务、主从臂、录制相机、FPS、时长和保存按钮。两处保存按钮都保存当前全部配置；未保存修改会提示。
- 开始采集：检查主从臂和相机，开启数据集/相机会话并切换采集模式。此步骤会使能，但不会自动对齐或录制。提供主从臂返回默认位置按钮。
- 采集区：小型相机画面、准备一集、确认并跳过准备语音、取消对齐、结束一集、保存结果和采样指标。采样节拍详情、最近保存详情与节拍报告直接完整显示，无需展开。页面底部操作说明与快捷键也始终显示。
- 结束采集：另一个主从臂回位入口、独立的结束采集按钮、独立的机械臂失能按钮、逐项结果和针对未完成项的重试。

语音设置位于顶栏。原有回位、失能确认弹窗以及准备语音跳过流程保留。
进入采集模式（包括回位后恢复示教）时，先使能主臂关节，再仅对主臂夹爪发送失能并等待新反馈确认，
清理此前的位置保持状态；随后确认夹爪示教参数设置成功，才进入主臂示教模式。
SDK 设置函数未确认时，主动查询并核对新的参数反馈（比例 100%、开口 70 mm、摩擦 8）；
不能仅因缺少设置 ACK 判定失败，也不能把旧缓存或无反馈当作确认成功。
任一步未确认就停止启动并显示对应主臂/CAN 通道，不失能七个关节、不向从臂发送跟随指令。
连续录下一集且无需恢复模式时，不重复这套切换；Ctrl+C 保持关节和夹爪上电的退出策略不变。
同一浏览器、同一工作台地址打开多个页面时，仅最近打开或操作的可见页面播报，
切换窗口或点击另一页面会停止原页面声音，避免“回位完成”等提示重叠。其他页面继续更新文字状态。
不同浏览器或不同访问地址不共享此机制，同时使用时请只在一个窗口开启语音。

## 遥操作模式与控制频率

数据集配置区提供两个遥操作模式，保留数据采样 FPS 的独立设置：

| 模式 | 指令 | 行为 |
| --- | --- | --- |
| 分离控制（低延迟） | `move_js` | 直接下发当前主臂目标，响应快 |
| 底层平滑（高延迟） | `move_j` | 由控制器平滑运动，跟随延迟较大 |

两个模式共用“控制频率”选项：**跟随采集、50 Hz、100 Hz、150 Hz、200 Hz**。
“跟随采集”按数据采样周期下发一次指令，修改 FPS 会同步改变目标控制频率；
固定频率则分别调度控制与数据采样，例如控制 150 Hz、采样 30 FPS。
默认延续 100 Hz，旧配置的 JS/J 选择会保留。原有轻度 EMA 平滑已删除，旧平滑字段读取时忽略、下次保存配置时移除。
开始采集后，模式、频率和 FPS 均锁定，结束采集后可修改；录制、状态页面和节拍报告采用已保存生效的配置。

两种模式均将主臂关节目标直接作为下发目标，`action` 对应最近一次已成功发出的目标；
没有隐藏的额外 EMA。报告保留控制频率选项、实测节拍和各配对指令，旧报告内容不改写。
J 模式正常到时、手动结束或异常退出时，都会在保存视频前读取从臂有效反馈，
用 `move_j(当前反馈角度)` 替换尚未完成的目标；这是保持位置请求，不代表已验证物理停稳。
无法读取有效位置或发送保持指令时，对该从臂尝试阻尼急停并锁定后续运动；双对中仍会收尾另一侧。
已有有效帧按原有规则保存并标记需复核，写入失败仍需处理。开始前未下发 J 目标时不额外发送保持指令。
保存视频期间不继续跟随，结束一集保持使能；回位和失能仍分别操作。

控制与图像采样在同一线程串行调度，避免额外线程并发写 CAN。
固定频率使用两套绝对时刻，相机读取或写盘阻塞仍可能延误控制，因此所选 Hz 是目标而非实时保证。
延误会跳过旧时刻并提示，不补发突发指令。页面分别显示实测控制 Hz、采样 FPS、最大间隔和错过时刻。
每个数据帧通过 `control_index` 关联最近完整控制周期，`control_age_ms` 显示该周期距采样时刻的年龄。
150/200 Hz 已覆盖软件调度测试，具体设备、CAN 与相机组合是否能稳定达到该频率仍以实测报告为准。

先结束采集，再重启工作台并刷新页面，选择模式和控制频率后保存配置。
建议保持采样 30 FPS，以相同小幅慢动作逐档比较颤动与跟随延迟，每次只改变一个参数。

### 数据格式与训练时间轴

以采样设置为 30 FPS 为例，这仍是 30 FPS 的 LeRobot 数据集：`meta/info.json` 的 FPS 为 30，`frame_index` 连续，
`timestamp = frame_index / 30`。`action` 是最近完整控制周期实际下发的目标，
`observation.state` 是该周期下发前读取的从臂反馈，图像是采样时取得的最新缓存帧。
两套绝对节拍不会简单地每 3 条控制指令保存一帧；100/30 并非整数，正常映射依次为控制周期 0、3、6、10、13、16……。
100 Hz 的中间命令保留在诊断报告中，标准训练数据只包含 30 FPS 的采样结果，无法无损复原所有高频运动细节。

以控制 100 Hz 为例，节拍正常时，选中的控制周期起点距采样时刻小于 10 ms；这不包含设备反馈自身的缓存年龄，
也不保证图像曝光与关节测量严格同步。重复相机帧、长帧龄、控制/采样漏拍仍需检查，
视频、Parquet 可读和格式兼容不能代替真机数据质量检查。
结束一集后，LeRobot 的 episode 元信息可能仍在缓冲；先点击“结束采集”完成数据收尾，再使用独立读取器或训练。

训练及动作序列解释应沿用 30 FPS。部署时若需 100 Hz 下发，应使用独立控制层并验证保持/插值、限速和平滑策略，
不能把 30 FPS 动作逐条按 100 Hz 播放，否则动作时长会缩短至原来的 30/100。
简单重复同一个目标不等于恢复了录制时的所有中间指令；高频接触、快速切换等任务需要额外验证是否丢失关键细节。
LeRobot 读取视频和时间窗时也使用 `timestamp`、FPS 和 `delta_timestamps`，并非完全不使用时间戳；
它不会自动根据独立设备的拍摄时刻修正传感器错位。

参考：[LeRobotDataset v3 格式](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)、
[官方部署的策略/记录 FPS 与插值控制频率说明](https://huggingface.co/docs/lerobot/main/inference)。
官方 `interpolation_multiplier` 为整数，30 FPS 对应 3 倍是 90 Hz、4 倍是 120 Hz；精确 100 Hz 需按时间调度，不能把 3 倍当成 100 Hz。

## 第四步：左右双对采集

原计划依次为：①模块拆分、②录制与保存流程、③采样质量、④左右双对同步采集、⑤数据列表与回放、⑥任务与审核、⑦训练和推理闭环。
第四步已完成并经用户真机验证；第五步的数据列表与回放已加入，按下一节验证浏览器播放与数据联动。

数据集配置区增加“机械臂采集模式”。旧配置默认保持单对，左右双对固定配为
**主左 → 从左、主右 → 从右**，CAN 编号可以任意分配，但四个角色必须各对应一个独立通道。
会话开启后不能修改模式、角色或数据参数。相机依旧可单独选左、右或两路，不由机械臂模式决定。

| 模式 | 状态和动作 | 续录规则 |
| --- | --- | --- |
| 单对 | 8 维，保留原来的 `joint1.pos` … `joint7.pos`、`gripper.pos` | 原有 8 维数据集继续可用 |
| 左右双对 | 16 维，`left.joint1.pos` … `left.gripper.pos`，再到 `right.joint1.pos` … `right.gripper.pos` | 单独使用双对数据集，不向 8 维数据集混写 |

两侧由同一个采样线程、同一个采样节拍驱动，每个时刻只写一行 16 维数据，属于同一集。
每轮先完整校验两侧关节与夹爪反馈，再按左、右顺序发送对应从臂的指令；夹爪动作记录限幅后实际发送值。
任一侧反馈无效或指令下发失败，停止整集后续跟随，保存此前完整帧并标记“已保存 · 需复核”；没有完整帧就不新增集。
下发途中的失败可能发生在另一侧已收到指令之后，该不完整帧不写入，也不自动重发或失能。

每集节拍报告新增模式、关节顺序、两组角色与 CAN 通道；逐帧保存两侧读取和下发的主机时间，以及各反馈源的原始时间戳。
这些用于核对共同软件时间轴，**不表示两路 CAN 指令原子执行或相机与机械臂硬件同步**。

准备时依次对齐左侧和右侧，最后再复核，两条主臂都应保持静止直到开录。
任意时刻取消准备/对齐都会取消整集。回位顺序为从左、从右、主左、主右，保持使能。
结束采集只收尾数据并让两条主臂退出示教；机械臂失能另行确认，弹窗列出四条臂，结果分别显示。
Ctrl+C 同样不发送关节或夹爪失能指令。

### 第四步真机验收

先结束当前采集，再按原方式重启程序并刷新工作台页面：

```bash
conda activate lerobot
python /home/jushen/Documents/Robot/lerobot/examples/nero_to_nero/record_platform.py
```

1. 分别用单对模式检查左、右两组跟随。结束各自会话后，连接四条臂，核对主左、从左、主右、从右的角色与 CAN 通道。
2. 选择“左右双对 · 16 维”，使用新的数据集名，例如 `nero/dual_step4`；选择相机，设为 10 秒、30 FPS，保存配置。
3. 开始采集、准备一集，保持两条主臂静止。确认左、右从臂依次对齐完成后才显示录制中。
4. 录三段短数据：仅缓慢操作左侧、仅缓慢操作右侧、两侧一起操作并包含夹爪开合。确认左右不串控制，停止一集时两侧一起结束。
5. 结束采集，检查四条臂仍保持使能。按需回位或托稳后单独确认四臂失能，再重启；配置应恢复为双对，可向同一数据集续录第 4 集。
6. 结束采集完成文件收尾后，运行只读检查：

```bash
python /home/jushen/Documents/Robot/lerobot/examples/nero_to_nero/verify_platform_dataset.py \
  --repo-id nero/dual_step4 --expect-mode dual --expected-episodes 4 --require-timing
```

通过标准：每集状态/动作都是 16 维且顺序固定；左右动作各自对应正确从臂；两侧共用集号和帧时间轴；每集每路相机独立 MP4，重启续录不覆盖旧集。
30 FPS 是否达到目标以真机节拍报告为准，软件模拟不能证明实际四通道负载或物理同步效果。

## 第五步：数据列表与回放

工作台顶栏“数据与回放”在新标签页打开 `/review`，也可直接访问 `http://127.0.0.1:5000/review`。
页面只读本地 LeRobot v3.0 的 Nero 单对/双对数据，不连接设备，不下发机械臂动作，不生成临时数据集或联网下载。

- 左侧选择数据集，按最新集在前分页显示集号、帧数、时长和节拍质量标记。右侧显示任务文本和实际保存参数。
- 右侧播放已保存的左右视频，统一播放/暂停、0.25～2 倍速、上一帧/下一帧和时间轴拖动。切换集会暂停并释放旧视频。
- 单对显示一组关节与夹爪；双对分别显示左、右。J1～J7 可切换，夹爪始终显示。实线为从臂反馈 `observation.state`，虚线为实际发送的目标 `action`。
- 曲线与数值按同一帧索引联动。界面将关节换算为角度、夹爪换算为毫米，原始数据仍是弧度/米。
- 完整显示节拍汇总、相机重复次数、帧龄与报告路径。逐帧的重复相机帧、采样错误、处理超时和较大采样间隔可点击定位；失败采样没有保存帧时定位到相邻有效帧，并显示原始主机时间。

LeRobot 的 Parquet 数据索引在会话收尾后才完整可读。因此，查看本次录制的集之前，需要在工作台点击
**结束采集**并等待成功，再到回放页刷新列表；仅“结束一集”还不够。此过程不需要失能机械臂，回放页也不会代为结束或失能。
当前仍开启会话的数据集会明确提示不可读取；其他已收尾的数据集可选择查看。

视频来源依据 `meta/episodes/` 中的相机文件和起止时间，不用集号猜文件名。旧的多集合并 MP4 按本集片段播放；
新录制仍是每集每路相机独立 MP4。时间轴采用保存的名义帧时间，不把主机报告的实际时间直接当作视频时间。
浏览器解码和多路播放存在误差，界面联动不证明物理同步。浏览器不能解码已有 AV1 视频或文件损坏时会显示提示，曲线仍可查看；不会在采集进程中自动转码。

缺失报告显示“缺少报告”，损坏报告显示具体原因，不伪报质量合格。视频缺失仍可读曲线；帧号缺失/重复、状态/动作无效或时间戳不匹配时拒绝显示可能错位的回放。
所有读取由用户刷新或选集触发，不加入采样循环和状态轮询。视频和数据读取仍会使用本机磁盘、CPU，建议集中在采集收尾后检查。

### 第五步验收顺序

1. 结束现有采集会话，按上面的命令重启程序并刷新工作台，点击顶栏“数据与回放”。
2. 先选已录好的 `nero/test03`：核对集数、帧数、左右视频，以及左/右关节与夹爪数值；再切换单对的旧数据检查兼容。
3. 播放、暂停、切换速度、拖动时间轴和逐帧移动，检查视频与曲线跟随同一位置。切换集后旧视频应立即停止，集末不进入下一集。
4. 点击“异常时刻”中的一项，检查跳转帧号和相机重复帧提示。不要把“需复核”直接等同于动作失败。
5. 再录一集：仅结束一集时，刷新回放应提示会话未收尾；结束采集完成后刷新，应能看到并播放新增集，机械臂状态由工作台的独立操作管理。

软件验证包含真实临时 LeRobot/MP4 读写、合并视频偏移、HTTP Range、文件只读、活动会话拦截，以及离线前端时间轴和异步切换测试。
实际浏览器的 AV1 解码与视觉联动按上述步骤验收。下一步再加入任务管理、审核标注与训练集筛选。

## 头部 Femto Mega RGBD

### 三路相机的分辨率与保存缩放

在数据集配置区的“录制相机”下，分别设置左、右、头部相机的采集分辨率、保存缩放。
先在左侧分配设备（每个角色均可使用 RGB 或已支持的 RGBD 设备），点击“读取所选设备分辨率”：读取设备声明的全部离散尺寸，
列表同时标出帧率；不支持当前目标 FPS 或 RGBD 硬件 D2C 的档位显示灰色。若驱动报告连续尺寸范围，显示范围和
步长，并列出最大、逐次减半、最小档位。查询不启动视频流，不加入状态轮询，采集会话期间禁止查询和修改。

每种采集分辨率可选原尺寸、宽高各 1/2、各 1/4 等；首次到宽 ≤640 **或**高 ≤480 后停止提供更小档位。
例如 1920×1080 → 960×540 → 480×270；1280×720 → 640×360；640×480 保留原尺寸。
页面同时显示采集与最终保存尺寸；保持原画面比例，编码所需的偶数边长向下取整，不强制裁成 640×480。
软件缩放降低保存量，不降低相机原始传输分辨率；若需降低 USB 带宽，选择设备支持的较低采集分辨率。

缩放在相机后台线程执行，采样线程只取缓存。RGB 用面积缩放；Femto 先完成硬件 D2C，再对 RGB 和深度使用
相同输出尺寸，深度用最近邻保留米值与无效零值。Femto 支持 RGB/BGR、MJPG 和 YUYV/UYVY 彩色格式的解码。
最终尺寸写入 LeRobot 特征与视频；节拍报告保存三路采集尺寸及缩放配置。开始采集时验证相机尺寸/帧率，
所有相机验证后才切换机械臂模式。**改变保存尺寸请换新数据集名**；不兼容续录会在切换设备模式前拒绝。
旧配置继续使用左/右 640×480、头部 1280×720 和原尺寸保存，读取能力列表不会擅自更改已保存的选择。

### 统一相机分配与录制内容

左侧只为当前检测到的设备统一编号“相机 1、相机 2……”；编号与用途无关，改用途不重命名、不重排。
用下拉框选择左、右、头部或未用；同一角色只允许一台。保存过但当前失联的设备单独显示，不占检测编号。

- **检测 RGB 相机**：刷新普通 UVC 设备和 RGB 预览，保留深度设备列表。
- **检测深度相机**：分别检测奥比 Femto、Azure Kinect 与 RealSense，保留 RGB 列表，不开启深度视频流、不重开 RGB 预览。
- 初次加载检测全部设备，随后读取缓存；检测按钮重新枚举。界面分别显示数量、SDK 缺失和检测失败，采集会话内禁止重新检测。
- Femto 列表序列号为空时，从 DeviceInfo 读取真实序列号；分辨率查询、连接也使用相同身份核对，避免显示出来仍找不到设备。
- RealSense 支持 RGBD 并排预览与录制，使用可选依赖 `pyrealsense2`；当前环境已安装。分配按 SDK 序列号识别物理设备，不按 `/dev/videoN` 的枚举顺序选机。其他环境缺 SDK 会直接显示提示。

Femto、Azure Kinect、RealSense 或 RGB 相机可分配为任意用途。
头部也可以使用普通 RGB，左右手部也可以使用 RGBD；多台 RGBD 按序列号分别持有句柄。
数据集配置区选择“左侧”“右侧”“左侧＋右侧”时，仍附带已分配的头部，兼容重构初版配置；
“仅头部”只录头部，“全部已分配角色”按实际分配录制。未分配、离线或不支持的选中设备会拒绝开始，不静默跳过。

| 设备角色 | RGB 字段 | RGBD 额外字段 |
| --- | --- | --- |
| 左 | `observation.images.left` | `observation.images.left_depth` |
| 右 | `observation.images.right` | `observation.images.right_depth` |
| 头部 | `observation.images.head` | `observation.images.head_depth` |

每台 RGBD 的 RGB 与深度取自同一完整快照；深度与同角色 RGB 对齐，保存尺寸由该角色的分辨率和缩放决定。
例如左 RGBD、右 RGB、头部 RGBD 共写入五路数据。界面按各角色显示彩色与深度预览，并合计深度临时存储量。
支持的 RGBD 设备在分配区以同组 RGB/深度并排预览；采集区在会话开启后复用录制相机的后台缓存。
开始采集前先释放 USB 预览句柄，避免同一相机被重复打开；所有录制相机验证完成后才切换机械臂模式。
任一相机打开失败会关闭已打开的录制句柄并恢复预览。

**从旧版固定 `observation.images.depth` 切换到按角色命名的深度时，请使用新数据集名。**
原视频与报告保持不动，旧 `depth` 字段、`head_camera` / `femto` 报告仍可回放。RGB 字段和保存尺寸未变时可继续录制原 RGB 数据集。
旧 `head_camera_mode/serial` 配置只有明确序列号时自动转为头部映射；没有序列号时保留一个缺失设备占位并显示提示，
须在界面将占位设为未用、重新分配真实设备再保存，避免旧版自动选择静默变成漏录头部。迁移不自动覆盖配置文件。

代码分工：`camera_model.py` 定义角色/流命名；`cameras.py` 负责发现和分配预览；
`depth_discovery.py` 注册各品牌的检测器，新增品牌可扩展 `DETECTORS`；
`camera_io.py` 将录制驱动适配成统一快照接口；`recorder.py` 仅遍历按角色保存的设备池；
`depth_images.py` 管理通用深度编码范围与伪彩色，回放不依赖某个相机厂商。
设备描述符分别用 `type`（rgb/rgbd）描述能力、`backend` 描述驱动。当前录制驱动是 OpenCV RGB、Orbbec Femto RGBD、Azure Kinect RGBD 和 RealSense RGBD。
RealSense 使用官方 SDK 的 [设备枚举与设备信息接口](https://realsenseai.github.io/librealsense/python_docs/_generated/pyrealsense2.html)。
增加其他品牌录制能力时，补充检测器并注册后端适配器，负责分辨率枚举、连接、缓存快照、预览；
RGBD 适配器必须提供米单位深度、匹配的 RGB/深度快照与真实时间戳元数据，不能只修改类型标签假装兼容。

### RealSense RGBD

`nero_platform/realsense.py` 独立封装 SDK；检测器、录制适配器、预览工厂分别注册，不在录制循环加入厂商分支。
界面分辨率来自所选设备的 RGB8 实际模式，并仅保留深度 Z16 也支持的 FPS；开始前还会核对 SDK 实际打开的尺寸、格式和设备身份。
深度优先选同尺寸、同 FPS，否则选相近尺寸，并用 `rs.align(rs.stream.color)` 按出厂标定投影到 RGB 像素坐标。
原始深度模式写入节拍报告；输出深度尺寸始终与同角色 RGB 一致。保存缩放在后台执行，深度用最近邻，按设备 `get_depth_scale()` 转米，零值保留。

后台单线程持续接收及对齐，录制循环只取不可变快照。开流先等连续新鲜帧；重复帧号不能刷新缓存帧龄，积压和过期帧会拒绝。
支持时请求 global time；每帧按实际时钟域分别记录设备/全局时间，缺失留空，不把设备时钟当作电脑时钟。主机接收元数据为 Unix 时间，缓存帧龄用单调时钟累计。
这些时差检查不等于跨设备同步曝光验证。

相机自检（关闭该相机预览/采集后运行；不连接机械臂）：

```bash
python examples/nero_to_nero/smoke_realsense.py --run --serial <SDK序列号> \
  --seconds 10 --width 1280 --height 720 --scale 2 --fps 30 \
  --report /tmp/realsense-smoke.json --preview /tmp/realsense-rgbd.png
```

### Femto RGBD

Femto SDK 请求 RGB、匹配的硬件 D2C 深度模式和完整 FrameSet；实际尺寸、像素格式、深度比例系数必须符合声明。
不支持所选 FPS / 分辨率时拒绝开始，不会偷偷回退到第一种模式。RGBD 的完整首帧验证在机械臂模式切换之前完成。
启动失败会尝试停止管线；收尾停止后台线程与 SDK 管线。未分配 Femto 时，不需要安装 Orbbec SDK。

Femto 后台线程等待 SDK，录制线程仅取加锁快照，不再每帧等待 50 ms。
RGB 和深度保留各自帧号、设备时间戳、全局时间戳与 SDK 主机接收时间，并共享一次完整 FrameSet 的缓存。
连接时先等待两路完整帧，再切换 SDK 同步模式清空配对队列，并排空已输出的旧 FrameSet；
清理后才发布首个快照。这样避免设备时间戳为零时，启动先到的 RGB 被持续配给较晚的深度。
清理只在相机后台启动时执行一次，失败会关闭相机并拒绝开始，不在录制循环等待 USB。
重复取用会计数，超过 500 ms 的旧缓存会拒绝。RGBD 缓存帧龄从完整 FrameSet 到达后台计算，不含 SDK 配对等待。
另用两路 SDK 主机接收时间检查积压：时差超过 `max(100 ms, 三个采样周期)` 时拒绝发布该帧，
录制端会显示错误并跳过本帧；持续异常时结束采集后重新开始采集。接收时间缺失时不虚构时差，
主机接收时差不能作为曝光同步证据。实时状态和节拍报告显示该时差，旧报告可重新计算提示。
报告按角色保存各设备序列号、模式参数、深度比例系数、有效 RGB/深度时间戳差、全无效帧和超出编码范围的帧数。
D2C 是同一 RGBD 设备两路的空间对齐；SDK 帧同步请求和时间戳检查分别展示，均不能据此声称和其他相机、机械臂同步曝光。

Femto 连接时在 SDK/设备支持的情况下请求 `enable_global_timestamp(True)`，记录请求结果；不支持或请求失败不阻止图像采集。
`get_timestamp_us()` 与 `get_global_timestamp_us()` 分别读取并保留，不混用两个时钟来源。只有同一来源的 RGB、深度
时间戳都为有效正值且连续推进，才计算时差；设备时钟优先，不可用时使用通过同样检查的全局时钟。
首帧等待连续性检查，零值/缺失/停滞/倒退显示“未验证”，时差为 `null`，不伪装成 `0 ms`。
即使设备报告支持且启用请求成功，也以每帧实际返回值为准；两类时间戳仍为零时不会借用主机接收时间冒充曝光时间。
有效时间戳最大差超过一个采样周期才触发配对告警。元数据异常不单独中断或丢弃正常图像；报告注明需要复核，
并显示已检查、未验证帧数。重复读取同一缓存不误报时钟停滞。旧报告回放时在内存中重新判断，不修改原文件。

### Azure Kinect DK

此驱动面向 Azure Kinect DK（USB `045e:097c/097d`），不适用于 Xbox Kinect v2。
Linux 检测从 sysfs 读取物理序列号，编号为 `k4a:<serial>`，不重复打开 SDK 预览；普通 RGB 扫描排除 Azure Kinect 的 UVC 节点。
启动时再通过 SDK 核对序列号，拒绝 USB 2.0 连接、错误分辨率/FPS；打开失败不会进入机械臂采集模式。

- 彩色使用 SDK BGRA32，在后台转换为 RGB；深度固定 NFOV_UNBINNED 640×576。
- 分辨率使用 SDK 的六种彩色模式，5/15/30 FPS；4096×3072 最高 15 FPS。缩放仍按各角色配置逐次减半。
- SDK 只返回完整同步 capture，再用出厂标定将深度投影到彩色坐标系（软件 D2C，不标为硬件 D2C）。
- 深度按最近邻缩小后从毫米转为 float32 米值；无效值保留 0，编码仍是 0～10 米。
- 记录真实设备微秒时间戳及主机单调时钟接收时间；不虚构全局时间戳或 SDK 帧号。
- 一个后台线程独占 SDK 句柄，`pyk4a` 的 `thread_safe=False` 使阻塞等帧释放 GIL；其他线程只读缓存，关闭前等待后台退出。
- 重复 SDK capture 不刷新缓存帧龄；接收时差过大或 SDK 帧积压超过 500 ms 会拒绝使用。

当前安装使用官方 libk4a 1.4.2 与 PyPI pyk4a 1.5.0。SDK 放在用户目录
`~/.local/share/nero/azure-kinect-sdk-1.4.2`，不替换系统库。Python 扩展链接到该目录，请勿在使用期间删除它。
Ubuntu 24.04 并非微软这版二进制的原始目标系统，导入通过不代表真机验证通过。

工作台重新启动后，检测深度相机、分配用途、读取分辨率、保存配置。初次可选 1280×720 并缩小一次保存 640×360。

平台不会自行提权或改系统参数。缓冲分配成功仍不代表出图正常；系统 V4L2 也报损坏数据时，应继续排查 USB 接口、线材、供电和驱动兼容性。

### 仅相机真机冒烟

先结束工作台采集，再显式运行（不连接 CAN、不保存图像、不创建 LeRobot 数据集）：

```bash
python examples/nero_to_nero/smoke_femto.py --run --seconds 5 --width 1280 --height 720 --scale 2 --fps 30
```

不加 `--run` 不打开设备。可用 `--serial` 指定相机，`--output 新路径.json` 保存元数据报告，不覆盖已有文件。
检查连续完整帧、RGB/深度尺寸和类型、深度值范围、帧号推进及时间戳可用性，结束或异常都会尝试关闭相机。
退出码 0 表示这些检查通过（不等同于同步曝光认证）；1 表示打开/图像/关闭失败；2 表示图像已检查但元数据或测距仍需复核。
普通 pytest 继续使用模拟 SDK；本脚本不会被默认测试自动调用。

深度按 `raw × get_depth_scale() / 1000` 换成 float32 米，无效值保留 0。
新数据的 HEVC 12-bit 深度编码范围明确为 **0～10 m**，避免默认最小深度 0.01 m 把无效 0 读成 1 cm。
12-bit 量化仍有误差；超过 10 m 的像素会饱和并在节拍报告中提示复核。旧的不同编码范围不能直接混合续录。
用 LeRobot 读深度时显式传入 `depth_output_unit="m"`；库默认返回毫米。

深度伪彩色固定为 0～10 m，零值黑色，**只用于显示，不替换保存数据**。
实时预览约 2 FPS，录制时复用提交给数据集的那一组 RGBD；每路深度标明对应的彩色角色。
回放页在服务器按保存参数解码深度，播放时最多每秒 5 次预览，暂停/拖动后显示所选帧；浏览器不必支持 HEVC 12-bit。
普通 RGB 视频下方增加浏览器解码丢帧统计和缓冲提示，与采集报告的重复缓存帧分别显示。

目前 LeRobot 在集结束时编码视频，此前会保存未压缩 float32 TIFF。
1280×720×4 bytes×30 FPS ≈ **110.6 MB/s**，100 秒约 **11.06 GB** 深度临时文件，尚不含 RGB / 文件开销；
界面根据本次各路 RGBD 的保存尺寸、FPS、时长合计估算。视频编码完成后清理临时图像。后台取帧不代表磁盘与 CPU 负载可忽略。

再录一集，检查四路字段、节拍、相机新鲜度、深度全无效 / 超范围提示。结束采集后回放，并执行：

## 三种结束操作

| 操作 | 数据处理 | 机械臂处理 |
| --- | --- | --- |
| 结束一集 | 保存当前片段，保留采集会话，可录下一集 | 保持使能 |
| 结束采集 | 停止本集、等待保存并关闭数据写入，恢复相机预览 | 退出主臂示教，不回位、不发送失能指令 |
| 机械臂失能 | 不重复数据收尾 | 会话结束后单独弹窗确认，原地失能所选主从臂及夹爪 |

回位会明确提醒第二关节 90°、其余 0°、先从臂后主臂、保持使能与夹爪状态。操作对象由当前单对或双对模式决定。失能会完整提醒托住机械臂或放缓冲垫、放稳夹持物、等待关节和夹爪反馈确认。数据收尾失败可以单独重试；也可先确认失能，失能不会重复处理数据。未执行失能与失能失败分别显示。

## 画面来源

未开启采集会话时显示所选设备的取景预览；录制时只显示成功提交给数据集的 RGB 采样帧，JPEG 编码在浏览器请求线程内执行；对齐、保存和集间等待时复用已打开相机的后台缓存作实时取景。不会为了显示画面再次打开相机。

页面约每 500 ms 请求一次画面（约 2 FPS），采样仍按配置的 30 FPS 等频率执行。预览超过 1 秒没有新的有效采样帧时不返回旧帧；网络请求超时或状态连接中断会隐藏旧画面并提示。预览不证明相机和机械臂已同步，实际采样质量仍以节拍指标和数据检查为准。

## 页面连接与保存状态

配置或相机列表第一次读取失败时，页面仍查询后台状态并自动重试；已经读取成功的配置不会因重试覆盖正在编辑的内容。
查询超过 5 秒会取消，失败后间隔 2 秒重试，正常时上一轮完成后再等 500 ms 查询，避免慢请求堆积。
断线期间顶部单独显示“后台运行状态暂未知”，保留数据保存错误，并锁定新增设备操作。
已知正在录制时仍可尝试“结束一集”；录制、回位、失能、保存等操作指令不会自动重发。
恢复连接后按后台实际状态更新按钮。状态接口只保留界面使用的硬件快照，去掉重复的关节/夹爪读取。

- **已保存**：本集保存完成，包括正常主动结束的短片段。
- **已保存 · 需复核**：数据已经保存，但存在反馈中断、采样质量警告或节拍报告写入失败。详情保留具体原因；排查设备后可准备下一集。
- **保存异常 · 暂停续录**：数据写入失败或已有帧未确认保存成功，禁止直接续录，需按错误提示处理。

关闭或刷新网页不会结束后台采集，也不会自动失能。会话未结束、设备仍使能、设备状态未知或操作进行中时，
页面请求浏览器显示离开确认；具体提示由浏览器决定，强制关闭进程等情况不能保证弹出。该提醒不下发任何设备指令。

## 真机试用顺序

### 每集独立视频

工作台对新建和续录数据集均按 **每个 episode、每路相机一个 MP4** 保存，不再拼接多集。
例如新数据集录两集、选择右相机时，会生成：

```text
videos/observation.images.right/chunk-000/file-000.mp4  # 第 1 集
videos/observation.images.right/chunk-000/file-001.mp4  # 第 2 集
```

选择左右两路时，左右相机各生成两个文件。每个新视频从 0 秒开始；对应帧数、时间戳和
episode 索引仍按 LeRobot 格式保存，可正常读取、训练和后续动作拆分。
重启续录时继续生成独立视频。旧数据集中已经合并的视频保持原样，后续新增集独立保存；
这类数据集的文件编号不一定等于 episode 编号，对应关系以 `meta/episodes/` 为准。

### 操作检查

1. 结束旧版会话并完成失能确认，再退出旧进程，启动并刷新网页：

   ```bash
   conda activate lerobot
   python /home/jushen/Documents/Robot/lerobot/examples/nero_to_nero/record_platform.py
   ```

2. 检查左侧四条臂的角色与状态，在左侧相机分配区用红/蓝物体核对颜色和左右来源。原数据集配置应保留，修改后可在任一保存按钮保存。
3. 点击“开始采集”，确认会话开启但没有录制。再从画面下方准备一集，测试跳过准备语音、对齐和 10 秒 / 30 FPS 录制，确认帧数接近 300。
4. 在采集区结束一集，确认保存结果出现、机械臂保持使能；可继续录下一集。左右两个回位入口应弹出相同提醒并执行同一回位流程。
5. 点击“结束采集”，确认仅保存和收尾，关节/夹爪未被失能。托稳后单独点击“机械臂失能”，检查完整语音、确认弹窗与每条臂的结果。准备/对齐时先取消并等结束，再执行会话收尾。

软件检查使用模拟 CAN、模拟相机、临时数据集；不代替此次布局和实机采样负载的验收。

## 反馈有效性与相机新鲜度

录制前确认主从关节和夹爪的时间戳都至少更新一次，该等待不计入本集时长。
录制中每次发送跟随指令前检查四路反馈：缺失、维数错误、NaN/Inf、无效时间戳或时间戳倒退时立即停止本集；
同一时间戳超过 0.5 秒未更新也停止。不会把缺失反馈补成零位指令。
此前有效帧会保存为提前结束的一集，页面明确标记“需复核”；没有有效帧就不新增集。
该处理不自动失能，机械臂可能继续保持最后目标位置。排查反馈后，再手动准备下一集。
夹爪动作按实际发送的 0～0.07 米限幅值写入数据。

相机快照同时取得图像、主机接收时间戳和帧龄，避免图像与时间戳来自不同帧。
循环可能重复取到同一缓存帧；页面和每集报告显示重复次数、最大帧龄，并提示复核。
暂时不通过等待相机新帧拖慢机械臂采样，也不删除重复帧破坏已有时间序列。
超过 500 ms 的相机帧仍会被拒绝。时间戳来自主机处理完成时刻，不是硬件曝光时刻；
同样的静态图像不等于重复采集，因此不以像素相同判定重复帧。

每集报告在 `meta/nero_timing/episode_XXXXXX.json`；新版为 schema 3（兼容读取 schema 1/2），含逐帧相机信息和异常结束原因。
只读验收同时兼容旧报告：

```bash
python examples/nero_to_nero/verify_platform_dataset.py --repo-id nero/你的数据集 --last-episodes 2 --require-timing
```

## 配置损坏与异常恢复

配置加载会校验类型、FPS、时长、数据集路径及设备分配；坏文件保持原样，页面显示具体路径与原因，
设备操作锁定。修复文件后重启。保存使用同目录临时文件、刷盘及原子替换；失败时保留原配置和内存设置。

对齐中断后先尝试按有效当前位置保持从臂。无法保持时尝试阻尼急停，并锁定后续录制、回位、微动。
页面不会将“发出急停请求”当成“确认急停生效”。先结束采集，托稳机械臂和夹持物，读取反馈；
若需失能，使用独立确认按钮。按设备说明处理急停或故障后，重启平台重新检查状态。
平台不自动复位或重新使能，也不假定所有固件都必须断电恢复。

Ctrl+C 会等待录制保存、退出示教并关闭相机，**不发送关节或夹爪失能指令**，保留使能以防误操作失去支撑。
失能始终由明确操作触发。数据保存失败会保留错误并阻止继续录制，不伪报保存成功。

语音设置、弹窗和多窗口播报见 [中文语音说明](README_PLATFORM_VOICE.md)。
