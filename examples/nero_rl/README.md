# NERO 右从臂：示范 + 人工接管 + SAC

## 使用原 VLA 采集的人工跟随（推荐）

配置 `action_mode: "joint_target"`、`hz: 100`、`gripper_max_m: 0.09`，使用右主臂输入：

```bash
uv run --no-sync python -m examples.nero_rl.run train \
  --config path/to/live_native.json --human-input master --execute \
  --web --web-host 0.0.0.0 --web-public-host 192.168.112.232 \
  --output outputs/nero_native_rl --episodes 20
```

人工控制与 VLA 工作台共用 `sampling.native_action` / `sampling.send_js_action`：
读取右主臂七关节绝对目标，直接下发 `move_js` 和夹爪目标（最多 90 mm，夹持力由配置指定）。
人工链路不经过 RL 的单步增量、3° 跟踪差或 TCP 工作盒限制，也不要求从固定任务起点开录。
首次“主臂跟随”仍使用 VLA 原有的主从对齐流程；对齐时保持主臂静止，按暂停可取消。
“相对接管（无需对齐）”以及已准备主臂后的恢复，会保持从臂当前位置并建立新的主臂参考，
不移动从臂去匹配主臂。相对目标为 `从臂接管位置 + 主臂当前位置 - 主臂接管位置`，
七关节和夹爪分别计算，仍经原生发送函数下发，不叠加 RL 的人工跟随运动过滤。
夹爪首帧保留此前的目标开度与夹持力，不会用物体挡住后的实测开度替换关闭目标。
相对模式按关节变化一比一映射，不是两臂末端在空间中的平移一比一映射。
可先暂停、把主臂放到舒服位置，再点击相对接管；接管后无需目测把两臂摆成相同姿态。
SDK 的现有限位设置、固件保护、反馈超时和夹爪驱动保护仍沿用原实现。

相机缓存在独立线程刷新；另一线程把每条实际指令与下一次关节反馈组成 RL 转移，
图像缩放、FK、回放记录不进入人工跟随循环。相机时间戳为主机接收时间，不能视为硬件曝光同步。
记录落后或图像失效会将本集标为不完整，人工跟随继续；不把丢失的数据标成成功。

动作契约为八维**绝对目标**：七关节 `q / π`，夹爪 `2w / gripper_max_m - 1`。
记录 SDK 限位裁剪和下发精度之后的目标，同时保存发送前的请求、控制时间和相机时间。
相对接管使用 `right_master_relative` 来源标签，并作为人工干预加入示范回放；
请求和动作均为换算后的从臂绝对目标，原有状态、动作及数据契约保持兼容。
状态为 17 维实测状态加上一条指令的八维绝对目标，便于 SAC 使用相同动作语义。
自主策略仍经过原有速度、关节、TCP 范围检查，并限制夹爪目标最多 70 mm。
策略切换要求当前 TCP 在自主区域内；自主限制不作用于人工示范。

已有模型的 `workspace_min_m / workspace_max_m` 同时定义训练时的坐标归一化，加载模型时保持不变。
原生 `joint_target` 模式可通过成对的 `policy_workspace_min_m / policy_workspace_max_m`
单独指定策略执行的 TCP 区域；未填写时沿用原范围。启动、路径检查和边界裁剪统一使用执行区域，
模型输入仍使用原归一化尺度。这两个执行参数不改变数据契约，完整配置仍随每集数据和模型保存。
更改执行区域前核对示范、实际任务布局和障碍物；示范覆盖范围只说明曾经到达，不代表整个包围盒经过碰撞验证。

原生 `joint_target` 配置可设置 `policy_workspace_enabled: false`，关闭自主策略的 XYZ
起点检查、执行前后越界停止和工作盒目标裁剪。`workspace_min_m / workspace_max_m` 仍仅用于
原模型的输入归一化，不能删改。该开关不改变已有数据和模型的坐标语义；速度、关节、
反馈有效性、人工暂停及设备急停处理保持原实现，页面会明确显示 XYZ 工作区限制已关闭。

浏览器先点“主臂跟随 / 人工接管”试操作，再点“开始本集”录制；
完成后点成功或失败保存、更新 SAC；暂停按钮保持当前位置。
网页模式保存后会保留控制页，允许继续补采；页面显示累计成功与失败集数。
终端模式按 `--episodes` 的总集数结束，失败集也计数。重启训练须通过 `--resume` 加载已保存模型。
此模式的数据和权重不能与旧版五维 TCP 或八维关节增量数据混用，使用独立输出目录。

`policy_reference_residual: true` 用于自主策略：七个关节输出围绕上一条指令作小幅随机修正，
范围匹配 `policy_joint_speed_deg_s / hz`；夹爪仍为绝对目标。采集格式与原始绝对目标保持一致，
人工 VLA 跟随不经过此模型。模型加载会检查该架构开关，不能直接把旧绝对均值模型当作修正模型。
SAC 的动作 log-probability 和熵目标包含这个缩放变换。
离线预热与验证结果不能替代真机成功率；使用 `eval --resume ... --output 独立目录` 做确定性测试，
测试结果单独保存。正式真机 RL 使用 `train`，并按成功/失败标签及人工接管经验继续更新。

设置 `--policy-burst-seconds 2` 后，独立 `eval` 页提供“从当前位置开始限时策略测试”。
此按钮仅在空闲时可用，先检查当前姿态和相机，再准备右从臂并保持其当前位置；
随后开始录制、执行一次限时策略，不调用主臂示教准备或主从对齐。主臂跟随仍由原按钮单独触发。
策略推理与记录使用同一份带接收时间戳的相机画面，缺失或过期时不发送策略动作。
页面状态接口包含模型文件名、最近读取的关节/TCP/夹爪反馈和策略相机年龄、跟踪及边界信息。
暂停和保存后不自动重新开始策略。

### 策略运行时让右主臂主动同步

原生 `joint_target` 的 `train/eval` 命令添加 `--active-master-sync`，页面会出现
“同步主臂到从臂”。该功能复用当前进程持有的 can3 连接，不启动第二个 CAN 控制器。

主臂处于失能时，先托稳并点击“主臂使能并原位保持”，该操作只锁定主臂当前实测姿态，
不开始追踪或夹爪同步。确认页面显示原位保持并能稳定支撑后，再松手点击同步。

- 首次同步：从臂保持当前位置，点击按钮让主臂以最多 5°/秒逐步接近从臂实测关节姿态；
  夹爪按实测开度同步，主臂夹持力为 1 N、开度变化速度最多 20 mm/秒。
- 开始策略：两臂初始最大关节差需在 2° 内；主臂跟随从臂实测反馈，不复制模型原始目标。
  主臂目标领先实测最多 1.5°，跟踪差超过 3°、主从差超过 5°或持续跟踪停滞时暂停。
- 人工接管：点击“相对接管”先停止两边的自主目标，再将主臂切回示教并释放其夹爪驱动，
  获取新参考后才开始接收手动增量。无需手动摆成完全相同的角度。
- 暂停、保存、退出与异常都取消主臂追踪并用实测位置保持；反馈不可用时采用原有阻尼停止回退。

主臂同步会真实驱动操作手柄，运行时不要抓住主臂强行拖动；等页面显示相对接管就绪再操作。
首次预对齐需要独立观察主臂工作区，关节插值与限速不能代替碰撞检查。
同步只改变控制权和跟随链路，不修改模型归一化或已有数据动作语义；原始 VLA 采集入口不变。

NERO 1.12 及之后固件的 `set_normal_mode()` 是无效兼容接口；主动同步使用
`set_follower_mode()` 并显式恢复 CAN 状态上报，不能沿用旧固件的 normal-mode 切换。
准备阶段尚未发出运动目标而丢失状态时，只记录故障并保持页面可用，不额外发阻尼停止；
运动中失去有效反馈时才请求一次停止回退，清理阶段不重复发送停止或覆盖原始错误。
初次主臂位置若略超出软件限位，可在明确点击同步时低速向内返回（最多超出 10°）；
目标仍须在原有限位内，不能继续向外，也不改变后续策略的限位。

### 离线训练视觉编码器

`train_visual_bc` 从成功示范训练视觉 CNN、状态编码器和动作均值输出，并训练仅用状态的对照模型。
监督路径显式允许编码器梯度，不使用 SAC actor 对共享编码器的梯度分离。
目标为约 100 ms 后的示范关节方向和绝对夹爪目标，保持原有绝对动作和坐标归一化。

```bash
uv run --no-sync python -m examples.nero_rl.train_visual_bc \
  --config path/to/native_residual_config.json --resume path/to/checkpoint.pt \
  --data path/to/demonstrations/episodes --split-file path/to/split.json \
  --output outputs/nero_visual_bc --device cuda
```

划分文件包含互不重叠的 `train_episodes`、`validation_episodes` 文件名列表。
按整集划分，仅加载成功真机示范；本轮验证集不得参与梯度更新。
若来源模型以前见过这些示范，报告仍应说明，不能把它称为从未见过的测试集。
报告保留仅状态模型、正确图像、空白图像、错配图像的验证损失和方向、夹爪误差。
视觉模型另用轻微亮度扰动和 10% 状态特征丢弃；状态对照保留完整状态。
这些指标不等于物体定位精度或真机成功率。

输出 `visual_checkpoint.pt` 与 `state_only_checkpoint.pt`，均可由现有运行器加载。
视觉编码器变化后，导出时重新初始化 SAC critic、优化器和更新计数，避免沿用不匹配的旧 Q 特征。
后续 RL 必须启用下面的预训练策略保护；BC 梯度步数与来源模型的历史 SAC 更新次数在报告中单独记录。
命令不连接机械臂，也不自动部署；已有输出目录非空时拒绝覆盖。

### 视觉预训练后的 RL 更新

新导出的视觉 BC checkpoint 会标记为需要保护，仍可直接推理；继续训练的配置添加：

```json
{
  "protect_pretrained_policy": true,
  "critic_warmup_updates": 1000,
  "bc_anchor_weight": 10.0,
  "rl_actor_learning_rate": 0.00003
}
```

从原始 BC 权重开始，先只训练价值网络，再训练动作网络。整个在线 RL 阶段冻结共享视觉和
状态编码器；保留图像输入，但不允许新初始化的价值网络改坏已学习的视觉特征。
动作损失加上对原 BC 策略的输出约束，使用无量纲的关节残差与绝对夹爪目标，避免 100 Hz
下微小关节动作导致约束失效。该参照随 checkpoint 保存，重启不会把新策略当成原参照。
价值目标不加入受残差坐标单位影响的熵常数；动作探索的熵项仍保留。
后续若要更新视觉编码器，另做视觉 BC 并重新验证、预热价值网络。

旧成功示范与新接管数据仍需要共同载入。仅混合回放不能保证不遗忘，更新后的模型还应在
固定的旧验证集与真机任务上分别检查；离线方向和夹爪误差不等于抓取成功率。
每次替换 checkpoint 前保存带更新次数和内容摘要的旧版本到 `checkpoints/`。
不要把已经退化的无保护 RL 模型设为参照；应加载保留的原始 BC 模型。

## 关节增量与浏览器控制

NERO 主臂实时示范可使用 `action_mode: "joint_delta"`：动作是七关节增量和夹爪增量，
`hz: 100` 为目标控制频率。增量基于上一条已发送的目标累计，人工输入由主臂关节目标产生，
经单步关节限制、TCP 区域和反馈检查后
流式下发 `move_js`；策略动作额外限制为 `policy_joint_speed_deg_s`（默认 5°/秒）。
目标接近领先实测关节 2.5° 时按反馈减慢推进，保留 3° 的硬跟踪限制；
受限关节持续 1 秒没有至少 0.1° 的正向跟进才暂停，不因短暂滞后直接中断。
暂停、结束和正常退出时用当前实测关节替换未完成目标；`control_events.jsonl` 保存暂停原因和各关节数据。
目标碰到 TCP 范围边界时，缩短关节目标增量到仍通过插值路径检查的位置，保持主臂输入，
向范围内移动即可继续。范围不扩大；若上一目标的路径也不可行，仍暂停并保持实测位置。
新目标在边界处保留 0.5 mm 余量，避免 SDK 下发角度量化把目标推到边界外。
关节模式的状态包含 17 维实测状态与 8 维上一指令，避免隐藏的累积目标。
本版不兼容旧版“相对实测位置增量”的关节示范及权重，请使用新的输出目录。
实际频率受相机、CPU 和 CAN 反馈影响，目标频率不等于实时性能保证。
该模式与下面旧版五维笛卡尔模式的示范、权重不能混用。

```bash
uv run --no-sync python -m examples.nero_rl.run train \
  --config path/to/live_joint.json --human-input master --execute \
  --web --web-host 0.0.0.0 --web-public-host 192.168.112.232 \
  --output outputs/nero_joint_rl --episodes 20
```

先退出占用相机和 CAN 的工作台。程序只连接、读反馈，等待浏览器点击“开始本集”才准备示教和运动。
使用输出目录 `control_url.txt` 中带会话令牌的链接打开页面。
默认人工示范；“成功/失败”保存一集，train 模式随后更新 SAC；“策略执行”需要已有成功示范。
开始前可按“人工接管 / 恢复”进行不录制的跟随调试或返回起点；页面显示实际频率和跟踪误差。
每集间恢复物体和指定起点。新配置、旧配置、模拟数据和真机数据都有独立契约检查。

## 五维笛卡尔模式

这一版训练独立的视觉 SAC 策略，不加载 π0.5。任务为**从桌面抓起木装饰，放入包装**。
复用仓库 `GaussianActorPolicy` 和 `SACAlgorithm`，不修改原来的 π0.5 推理流程。
这是 HIL-SERL 风格的最小本机流程，不是论文完整复现，也不是已有成功率的成品策略。

## 已实现

- 单右从臂 `can1`，头部和右腕 RGB，关节 + TCP + 夹爪状态。
- 5 维归一化动作：基坐标系 `Δx, Δy, Δz, Δyaw, Δ夹爪开度`。初始 roll/pitch 随机器人姿态保留。
- 人工演示、策略执行、随时切回人工、人工成功/失败标签。
- `--human-input master`：右主臂 `can3` 控制右从臂 `can1`，与策略共用 5 维增量动作和约束。
- 在线数据和人工数据混合回放；SAC 更新 actor、critic 和温度。
- 每集动作结束后更新模型，训练时不发运动指令；不是异步分布式 learner。
- 保存原始图像、实际通过约束的动作、请求动作、标签、接管标记、耗时和约束拒绝记录。
- 保存并恢复模型、critic、优化器与随机状态；从保存的 episode 重建有限回放池。
- 真机和 mock、不同工作空间或动作尺度的数据/权重不能混用。

## 先验证软件（不接机械臂）

在仓库根目录：

```bash
uv run --no-sync python -m examples.nero_rl.run smoke --output outputs/nero_rl_smoke
uv run --no-sync pytest tests/rl/nero -q
```

`smoke` 使用**合成点夹爪**生成抓放轨迹，跑真正的 SAC 梯度更新，保存后重新加载并检查推理结果。
它只验证软件链路，不模拟 NERO 动力学、碰撞或接触，不证明真机能完成任务。

当前环境已能导入 SAC；若使用其他环境，先安装项目相应依赖。真机还需要 `pyAgxArm`、
SocketCAN 和相机权限。模块导入和 smoke 不调用 CAN SDK。

## 真机前需要测定的配置

现场采点、TCP 拟合和配置草稿生成步骤见 [CALIBRATION.md](CALIBRATION.md)。

复制 `examples/nero_rl/right_packaging.json` 到自己的配置文件。
相机路径来自现有采集平台配置，仍需核对插拔后的设备身份。可以只读检查：

```bash
uv run --no-sync python -m examples.nero_rl.run inspect \
  --config examples/nero_rl/right_packaging.json --output outputs/nero_rl_inspect
```

该命令只连接、读反馈和拍照，不使能、不复位、不发运动。`tcp_offset_m` 未填写时，
输出位置明确标为 **SDK link7**，不能把它当作夹爪抓取中心。

实际启动前填写：

- `tcp_offset_m`：**实际夹持中心**相对 SDK link7 的平移，米。不能直接照搬模型指尖偏移。
- `workspace_min_m / workspace_max_m`：覆盖木件和包装、经过现场验证的 TCP 工作范围，米、右臂基坐标系。
- `start_joints_rad`：每集开始的实测 7 关节位置，弧度。机器人需先停在此姿态附近。
- 核对相机，确认整个允许区域内的臂杆、手指、桌面和盒子碰撞风险后，设置 `geometry_verified: true`。
- 有可用 GPU 时将 `device` 改为 `cuda`；不要假定当前进程能访问 GPU。

工作范围是操作者设定的任务约束，不是通过一次抓放就能完成的安全认证。
可以直接填写已知、经过现场检查的 XYZ 边界，**不要求先运行 `workspace` 扫描或另外采一遍路线**。
轨迹的最小/最大坐标只描述已访问的位置，至多用来辅助选择边界或发现边界过小；
它既不包含所有可用位置，也不能证明包围盒内部、手指或臂杆都不会碰撞。
当前程序需要这些数值用于动作裁剪和坐标归一化；现场环境安全与这些软件参数应分别确认。

程序检查 TCP 工作范围、采样的关节插值路径、关节限位、单步角度、反馈新鲜度和到位状态。
**这不是完整碰撞检测或接触力控制**，`geometry_verified` 也不代替物理标定。
运动输出只允许右从臂 `can1`；选择主臂输入时还会将右主臂 `can3` 准备为示教模式，不操作左侧。
默认 `move_j` 速度设为 1%，每步 1 mm / 1° / 2 mm 夹爪，
关节目标最多变化 0.5°；未到位会超时停止，不能保证固定 5 Hz。

## 1. 人工采集示范

现场停掉 π0.5 推理和遥操作程序；将右臂放到已验证的起始姿态，物体和包装放到任务区域。
主臂输入还要求退出 `record_platform.py` 工作台进程，释放 CAN 控制和相机；仅停止网页里的遥操作不够。
工作台同机默认地址为 `http://127.0.0.1:5000`，程序启动及运行中会检查它是否关闭。
如果工作台使用其他端口，须通过 `--workbench-url http://127.0.0.1:端口` 指定实际地址。

### 使用右主臂示范（推荐）

```bash
uv run --no-sync python -m examples.nero_rl.run record \
  --config path/to/right_packaging_calibrated.json --execute \
  --human-input master --output outputs/nero_rl_master_demos --episodes 20 --preview
```

这里的配置必须已完成 TCP、起点和工作范围检查；尚未填写工作范围或 `geometry_verified: false`
的草稿会被拒绝，不能把草稿改名当作已验证配置。当前物体类型以配置中的 `task` 为准。

- 按 `n` 开始本集并准备右主臂示教；程序取主臂当前位置为参考，**不将从臂自动对齐到主臂**。
- 移动主臂控制相对 XYZ；默认主臂位移乘 `0.25`，可用 `--master-translation-scale` 在 `(0, 1]` 内调整。
  两台臂使用各自基座坐标轴，安装方向不同需先小幅验证方向。
- 转动主臂控制绕基座 Z 的相对转动；捏合/张开主臂夹爪控制从臂开度的相对变化。
  当前动作空间保留从臂 roll/pitch，**不是完整七关节的一比一跟随**。
- 按 `p` 暂停跟随，可以把主臂移到更舒服的位置；按 `i` 从新的主臂位置继续。
  策略执行时同样按 `i` 人工接管；移动主臂本身不会自动触发接管。
- 慢速移动。每个控制周期仍限于配置的增量；超出部分被丢弃，不积压、不在主臂停下后继续追赶。
  如果一次循环超过 0.5 秒，会丢弃这段主臂位移并重新取参考。
- 主臂没有参与普通工作台的绝对关节跟随；它只生成归一化请求，随后经过相同的工作空间、IK、
  关节步长和夹爪约束。保存的 `action` 是通过检查后下发的增量指令，`requested_action`
  是输入请求，`action_source` 区分 `right_master` / `keyboard` / `policy` / `outcome`。
- `1 / 0` 标记成功/失败；`q` 保存退出；`x / Ctrl+C` 请求右从臂阻尼停止。
  主臂退出时恢复受控模式，关节保持使能，不自动回位或失能。
- 每集之间默认不跟随：按 `i` 用主臂把从臂移回起点，按 `p` 保持；恢复物体和盒子后按 `n`。
  集间移动不进入训练；主臂在集间可暂停、重定位后再次按 `i`。

主臂输入模式与键盘输入模式的数据使用相同动作契约，可混合加载。旧工作台的绝对关节数据仍不能直接混入。
当前实现已做离线验证；真实 CAN、夹爪示教、方向和操作手感仍需低速现场验收。

### 使用键盘示范（保留）

在可操作键盘的现场终端运行：

```bash
uv run --no-sync python -m examples.nero_rl.run record \
  --config path/to/right_packaging_calibrated.json --execute \
  --output outputs/nero_rl_demos --episodes 20 --preview
```

无桌面环境时去掉 `--preview`。终端按键：

| 按键 | 动作 |
|---|---|
| `n` | 场景复原后开始本集；此时准备电机，不自动移动到起点 |
| `d / v` | 基坐标系 +X / −X |
| `w / s` | +Y / −Y |
| `r / f` | +Z / −Z |
| `j / k` | 绕基坐标系 Z 正转 / 反转 |
| `o / c` | 打开 / 关闭夹爪 |
| `i` | 人工接管并继续 |
| `a` | train/eval 模式切换策略自主动作 |
| `p` | 暂停，保持已到位姿态 |
| `1 / 0` | 确认成功 / 确认失败，结束本集 |
| `q` | 退出；保存已有过渡，保持力矩 |
| `x / Ctrl+C` | 请求控制器阻尼停止并退出 |

每次按键/键盘重复只执行一个小增量，松开就是保持。机械动作中 `x` 的检测仍依赖软件与 CAN；
物理急停需保持可用。NERO 的电子急停是阻尼停止，抬起的臂可能下降，不等同于锁死位置。

成功标签应在木件放入目标位置、夹爪释放、撤开且物体稳定后给出。
到达时间上限是截断，不自动算成功。先收集几十条覆盖不同抓取位置和失败恢复的示范，
这个数量只是起点，不是成功保证。每集之间用本程序的 jog 键回到起始位置；人工恢复木件和包装。
这些集间动作不进入训练。不要同时运行另一套控制程序。

## 2. 开始真机 RL

```bash
uv run --no-sync python -m examples.nero_rl.run train \
  --config path/to/right_packaging_calibrated.json --execute \
  --human-input master \
  --data outputs/nero_rl_master_demos/episodes --output outputs/nero_rl_train \
  --episodes 100 --preview
```

每集默认人工控制。按 `a` 才切到策略；主臂模式按 `i` 重新取参考并接管，任一 jog 键也可立即切回人工。
早期策略未经充分训练，应频繁接管；演示和接管动作加入人工回放池。
每集结束后，用一半在线样本、一半人工样本更新 SAC（没有人工样本时仅在线采样）。
**不能按 `a` 开始自主动作直到至少有人工数据。** 第一版奖励只在人工确认成功时为 1；
尚未接入视觉奖励分类器，不会自行识别木件是否真的装好。

恢复训练：

```bash
uv run --no-sync python -m examples.nero_rl.run train \
  --config path/to/right_packaging_calibrated.json --execute \
  --human-input master \
  --data outputs/nero_rl_master_demos/episodes --output outputs/nero_rl_train \
  --resume outputs/nero_rl_train/checkpoint.pt --preview
```

## 3. 单独评估

```bash
uv run --no-sync python -m examples.nero_rl.run eval \
  --config path/to/right_packaging_calibrated.json --execute \
  --human-input master \
  --resume outputs/nero_rl_train/checkpoint.pt \
  --output outputs/nero_rl_eval --episodes 20 --preview
```

评估使用确定性动作，不更新权重；统计保存在 `metrics.jsonl`。有人工介入的成功应与完全自主成功分开统计。
演示/接管仍可用于诊断，但 `eval` 文件不会被自动加载进训练。

## 限制

- 此次实现和离线验证不等于真机验收。还需要现场标定、只读检查、手动 jog 验证、采集与训练。
- 旧 π0.5 数据的动作是绝对关节/EEF 目标，不能直接拿来做本流程的增量动作标签。
- 第一版只学 xyz、yaw 和夹爪；要求任务在起始 roll/pitch 下可完成。
- 真机配置的 120 秒是动作步数预算；低速未到位等待、人工暂停会延长实际用时，可按任务调整配置。
- 正常退出保持电机力矩，不自动回位失能。需要回位失能时，退出此程序后使用已有控制平台。
- 发生故障/反馈过期时请求阻尼停止，保存已完成的数据并退出；不自动重试、复位或重新使能。
