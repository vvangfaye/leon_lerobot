# 右臂任务标定

`calibrate` 只读右从臂 `can1` 的反馈。不会使能、失能、回位、切换模式或发送移动命令。
用原控制台调整姿态、停止遥操作，等臂稳定后采点。不要在采点时拖动。

也可在工作台设备区使用“右从臂直接拖动”，直接扶右臂摆姿态；它不会保存关节限位。
保持夹爪开度不变，摆好后点击“结束右从臂拖动”恢复位置保持，再运行只读采点命令。
若释放夹爪后开度与前面样本相差超过 1 mm，当前拟合会拒绝混用，需重新确认夹爪开度或重采。

## TCP：4 个拟合姿态 + 至少 1 个独立检查姿态

参考点必须固定不动且高度明确。固定硬板上的黑点可以；仅在相机里看着重合不够。
两指间选定的抓取中心每次都对准同一三维点，夹爪开度保持不变。
换姿态前先退开，改变朝向后再靠近参考点，不要顶住参考点扭转工具。
不同姿态需要绕多个轴改变朝向，只有水平旋转无法求完整 TCP。

第一个姿态：

```bash
uv run --no-sync python -m examples.nero_rl.calibrate capture \
  --config examples/nero_rl/right_packaging.json \
  --session outputs/nero_calibration/session_01 \
  --kind tcp --name tcp_01 --reference grasp_center
```

以后用同样命令，将名称改为 `tcp_02`、`tcp_03`、`tcp_04`。
姿态编号不能重复，原始记录不会被覆盖。程序采 20 次稳定反馈；检测到晃动会拒绝保存。
每次保存相机图和 `sample.json`，汇总在 `session.json`。
TCP 已填写的旧配置也不会污染采样：工具强制读取原始 link7 坐标。

若原工作台正在显示相机预览，采点命令加 `--no-images`，避免两个程序同时打开同一相机。
此时仍保存完整关节和位姿数据，画面在工作台复核。

再换一个区别于前四次的朝向，用 `--kind tcp_check --name check_01` 采点。
这个姿态不参与拟合，用于独立检查。

```bash
uv run --no-sync python -m examples.nero_rl.calibrate fit \
  --session outputs/nero_calibration/session_01
```

查看 `accepted` 和 `tcp_fit.json`。默认每点误差上限 1.5 mm；这是初始验收阈值，
不代表绝对精度保证。朝向变化不足、检查姿态重复或对点不准不能算标定成功。
残差较大时应检查固定参考点、抓取中心定义和摆姿态质量，不要自动扩大阈值。

如果对准的是辅助标定尖端，首次用 `--reference auxiliary_tip`。
拟合得到的是尖端偏移，不能直接用作抓取中心；生成配置时必须提供实测的
`--grasp-offset-mm dx dy dz`，表示从标定尖端指向抓取中心、按 **link7 三轴**表达的向量。

## 工作范围和起始姿态

若已知现场允许的 XYZ 边界，可以直接填写配置的 `workspace_min_m / workspace_max_m`，
不必单独采集工作范围。一次示范不能测出完整可用空间，也不能证明其中所有位置安全。
工作范围是明确设定的任务约束；示范可以辅助检查这些约束是否覆盖任务。

需要用采点辅助生成草稿时，完成 TCP 后，用同一采点命令记录：

- `--kind workspace --name bound_01` 等：至少四个经过现场检查的边界姿态，覆盖任务的 x/y/z 范围。
- `--kind start --name start`：恰好一个每集起始姿态。

TCP 拟合阶段参考点不能改变；workspace/start 阶段正常移动，不再要求对准参考点。
所有样本仍记录 link7，由已拟合的 TCP 计算位置。
起始姿态和工作边界必须满足 RL 的保守关节限位；超限时不会自动放宽。

```bash
uv run --no-sync python -m examples.nero_rl.calibrate build \
  --session outputs/nero_calibration/session_01 \
  --config examples/nero_rl/right_packaging.json \
  --output outputs/nero_calibration/right_packaging_draft.json
```

生成的范围是采样点的轴对齐包围盒。采过边界不等于整个盒内都无碰撞，
也不能证明手指、臂杆或相机支架的扫掠空间安全。
程序始终保持 `geometry_verified: false`；现场核对允许范围，并完成低速手动验证后再启用。
若参考点、工具安装或相机布置发生改变，应分别重新标定或重新核对。

操作者明确接受当前较粗的 TCP 精度时，`build --accept-coarse` 可生成粗标定草稿。
它仍要求至少一组不同朝向的独立复核，保留原来的阈值是否通过、拟合误差和复核误差，
并写入同名 `.quality.json` 文件。它不把失败结果改成精标通过，也不自动设置 `geometry_verified`。

## 手动摆姿态

```bash
uv run --no-sync python examples/nero_to_nero/record_platform.py
```

浏览器打开 `http://127.0.0.1:5000`，选择单对：主右 `can3` → 从右 `can1`，保存配置，
连接这两条臂，使用“遥操作测试”。此按钮会使能并先让从臂对齐主臂，启动前检查路径并保持主臂静止。
对齐完成后慢慢拖主右；摆好姿态后“停止遥操作测试”，等待从臂稳定再采点。
此过程无需录制 LeRobot 数据集。不使用“关节限位测量”代替本流程。

## 需要更高精度时

先约定任务允许的位置误差，并区分 TCP 拟合误差与整机绝对定位误差。
本工具估计的是 link7 到所选工具点的平移，不校正关节零位、连杆参数、受力挠曲或相机外参。
`fit_errors_mm` 很小不等于工具在整个工作区具有同样绝对精度。

- 用不会弯曲或滑动的标定杆和固定定位座，代替目测对准悬空的抓取中心。固定件不能随接触移动。
- 若采用球头杆与锥窝，定位的是球心；应限制朝向，避免杆碰窝口或接触用力造成挠曲。
- CAD 尺寸不能单独证明实物尺寸。辅助标定点到实际抓取中心的转换也需要实测或独立复核。
- 建议采 8–12 个拟合姿态，朝向覆盖多个轴；另采至少 3 个不同姿态作独立检查。这是本项目的采样建议，不是精度保证。
- 每次换姿态先脱离定位座，再改变朝向、重新轻触定位。停止遥操作并等到位姿稳定后采点。
- 拟合和独立检查都不通过时检查夹持滑动、定位座移动、接触变形和朝向分布，不自动删除误差大的点或放宽阈值。
- 完成工具点拟合后，还需在真实抓取及包装区域验证位置、方向和重复对位，并记录实际误差。
- 若要求亚毫米绝对定位，需要独立测量手段检验；只靠相机目测、普通打印件和拟合残差不能作出该保证。
